# Threat Service

REST-сервис для обмена информацией об угрозах (вредоносных файлах). Угроза идентифицируется
MD5-хешем файла. Сервис написан на Go по OpenAPI-спецификации из [`api/openapi.yaml`](api/openapi.yaml).

## Что умеет

| Метод | Путь | Описание | Коды ответа |
|---|---|---|---|
| `POST` | `/info` | создать запись | 201, 400, 401, 409, 429, 500 |
| `GET` | `/info/{md5}` | получить запись | 200, 400, 401, 404, 429, 500 |
| `PUT` | `/info/{md5}` | полностью заменить запись | 200, 400, 401, 404, 429, 500 |
| `GET` | `/healthz` | проверка живости (без ключа и лимитов) | 200 |

Все ошибки приходят в формате из спеки: `{"message": "...", "details": "..."}`.

### Модель угрозы

В исходной спецификации были только `md5` и `name`. Я добавил поля, которые реально нужны,
чтобы описать угрозу, и сделал их необязательными, чтобы не ломать совместимость:

| Поле | Тип | Правила |
|---|---|---|
| `md5` | string | **обязательное**, 32 hex-символа; хранится в нижнем регистре (`ABC…` и `abc…` — одна запись) |
| `name` | string | **обязательное**, 1–255 символов |
| `sha256` | string | 64 hex-символа |
| `type` | enum | `trojan`, `ransomware`, `worm`, `virus`, `backdoor`, `spyware`, `adware`, `miner`, `other` |
| `severity` | enum | `low`, `medium`, `high`, `critical` |
| `file_size` | integer | ≥ 0, в байтах (`0` — допустимое значение: у пустого файла MD5 как раз `d41d8cd9…`) |
| `description` | string | до 2000 символов |
| `created_at`, `updated_at` | date-time | только в ответе, выставляет сервер |

Валидация возвращает **все** найденные проблемы сразу, а не по одной:

```json
{"message": "Validation failed",
 "details": "md5: must be 32 hexadecimal characters; name: is required"}
```

`PUT` заменяет запись целиком: необязательные поля, которых нет в запросе, очищаются.
`md5` и `created_at` не меняются.

## Быстрый старт

### Вариант 1: Docker (сервис + PostgreSQL)

```bash
cp .env.example .env        # впишите свой API_KEY
go mod tidy                 # один раз: создаст go.sum (нужен для сборки образа)
docker compose up --build
```

Сервис доступен на `http://localhost:8080`, данные лежат в PostgreSQL (том `pgdata`).

### Вариант 2: локально, без Docker и без базы

Нужен Go 1.23 или новее (`go version`). В репозиториях Ubuntu он часто старый, актуальную
версию можно взять на [go.dev/dl](https://go.dev/dl/).

```bash
go mod tidy
make run                    # данные хранятся в памяти и пропадут при перезапуске
```

### Пример запросов

```bash
KEY=change-me   # то, что указали в API_KEY (если он не задан, заголовок не нужен)

# создать
curl -i -X POST localhost:8080/info -H "X-API-Key: $KEY" -d '{
  "md5": "d41d8cd98f00b204e9800998ecf8427e",
  "name": "Trojan.Win32.Generic",
  "type": "trojan",
  "severity": "high",
  "file_size": 48213
}'

# получить
curl localhost:8080/info/d41d8cd98f00b204e9800998ecf8427e -H "X-API-Key: $KEY"

# обновить
curl -X PUT localhost:8080/info/d41d8cd98f00b204e9800998ecf8427e -H "X-API-Key: $KEY" \
  -d '{"name": "Trojan.Win32.Updated", "severity": "critical"}'
```

## Настройки (переменные окружения)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `HTTP_ADDR` | `:8080` | адрес и порт |
| `DATABASE_URL` | пусто | строка подключения к PostgreSQL. **Если не задана — хранилище в памяти** |
| `API_KEY` | пусто | ключ для заголовка `X-API-Key`. **Если не задан — авторизация выключена** (в лог пишется предупреждение) |
| `RATE_LIMIT_RPS` | `10` | запросов в секунду с одного IP; `0` — выключить |
| `RATE_LIMIT_BURST` | `20` | допустимый кратковременный всплеск |
| `TLS_CERT_FILE`, `TLS_KEY_FILE` | пусто | если заданы оба — сервис работает по HTTPS |

Чтобы попробовать HTTPS: `make certs`, затем
`TLS_CERT_FILE=certs/cert.pem TLS_KEY_FILE=certs/key.pem make run` и
`curl --cacert certs/cert.pem https://localhost:8080/healthz`.

## Тесты

```bash
make test               # юнит- и интеграционные тесты
make test-integration   # то же + тесты хранилища на настоящем PostgreSQL (поднимет его в Docker)
```

- **Юнит-тесты**: валидация (`domain`), бизнес-логика (`service`), маппинг ошибок в HTTP-коды (`handler`),
  middleware, конфиг.
- **Интеграционные тесты** (`internal/server`): поднимается настоящий HTTP-сервер со всей цепочкой
  middleware, и тест ходит в него как внешний клиент: полный жизненный цикл записи, формат ошибок,
  API-ключ, rate-limit, лимит размера тела.
- **Тесты PostgreSQL** (`internal/storage/postgres`) запускаются, только если задана `TEST_DATABASE_URL`,
  поэтому обычный `go test ./...` работает и без базы.

## Устройство проекта

```
api/openapi.yaml            спецификация (источник истины для контракта)
cmd/server/                 точка входа: конфиг, выбор хранилища, запуск, graceful shutdown
internal/
  domain/                   модель Threat, правила валидации, доменные ошибки
  service/                  бизнес-логика + интерфейс Repository
  storage/memory/           хранилище в памяти (тесты, быстрый запуск)
  storage/postgres/         хранилище на PostgreSQL (pgx) + schema.sql
  handler/                  HTTP-слой: JSON → вызов сервиса → ответ по спеке
  middleware/               recover, логирование, лимит тела, API-ключ, rate-limit
  server/                   сборка маршрутов и middleware в один http.Handler
  config/                   чтение настроек из окружения
  httpjson/                 единый формат JSON-ответов и ошибок
```

Зависимости направлены в одну сторону: `handler → service → Repository (интерфейс) ← storage`.
`domain` ни от чего не зависит. Благодаря этому сервис тестируется с хранилищем в памяти,
а в бою подставляется PostgreSQL, и менять ничего не нужно.

## Принятые решения

- **Стандартная библиотека вместо фреймворка.** Роутер `net/http` с Go 1.22 умеет `GET /info/{md5}`,
  внешний роутер тут не нужен. Единственная внешняя зависимость — драйвер `pgx`.
- **Схема БД создаётся при старте** (`schema.sql`, идемпотентно). Для одной таблицы это проще
  и надёжнее, чем отдельный инструмент миграций. Если схема начнёт расти — стоит перейти на `golang-migrate`.
- **MD5 нормализуется в нижний регистр**, иначе одну и ту же угрозу можно было бы создать дважды.
  Проверка формата дублируется ограничением `CHECK` в БД.
- **Внутренние ошибки не утекают клиенту.** Всё неожиданное (например, недоступная база) логируется,
  а клиент получает `500 Internal server error` без подробностей.
- **Защита**: API-ключ (сравнение за постоянное время), rate-limit по IP (token bucket, без внешних
  зависимостей), ограничение размера тела (1 МБ), таймауты HTTP-сервера, опциональный TLS,
  контейнер запускается не от root.

## Ограничения и что можно улучшить

- Rate-limit считает по адресу соединения. За reverse-proxy нужно учитывать `X-Forwarded-For`,
  и доверять ему только от своего прокси.
- Один общий API-ключ. Для нескольких потребителей лучше ключи по клиентам или JWT.
